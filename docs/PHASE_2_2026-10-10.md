# Aşama 2 — güvenli dış bağlantı, DB hedef kontrolü ve öğretici

## Uygulanan değişiklikler

- Webhook adresleri HTTPS/443 ve gerçek DNS hostname ile sınırlandırıldı. Kimlik bilgisi, fragment, IP literal, yerel ad, özel/rezerve IPv4 ve IPv6 geçiş adresleri reddedilir. DNS yanıtlarından biri bile yasaksa tüm istek reddedilir.
- Production webhook gönderiminde `HCSC_OUTBOUND_ALLOWED_HOSTS` zorunludur. Liste **tam hostname** eşleştirir; ana domaine izin verilmesi alt domainleri onaylamaz. Her gönderimde DNS yeniden doğrulanır; kontrol edilen IP socket lookup'a sabitlenir. TLS sertifikası/SNI asıl hostname ile doğrulanır.
- Redirect izlenmez. DNS en fazla 2 saniye, toplam gönderim 5 saniye; istek 256 KiB ve yanıt 64 KiB ile sınırlıdır. Bir event için en fazla dört eşzamanlı gönderim yapılır. Politika engeli `blocked`, ağ/şifreleme hatası `failed`, HTTP reddi `rejected` olur; yalnızca 2xx `delivered` sayılır. Bu, alıcı uygulamanın işlediği anlamına gelmez.
- Endpoint oluşturma hataları ham Prisma/DNS/şifreleme ayrıntılarını API yanıtına taşımaz.
- DB bağlantısı ve Prisma DB komutları hedef parmak iziyle kontrol edilir. Test hesabı, seed, migrate dev/reset, db push ve fixture kapatma komutları production'da reddedilir. `DATABASE_URL` / `DIRECT_URL` farklı hedefse işlem engellenir. Neon pooled/direct eşdeğerliği normalize edilir.
- `VERCEL_ENV=preview`, `NODE_ENV=production` olsa bile production sayılmaz. Uzak test/preview hedefi production parmak iziyle eşleşemez. Normal uygulama ve bakım komutları da kontrol edilir. Bu kontrol DB kullanıcısının en az yetkiyle sınırlandırılması veya gerçek fiziksel izolasyonun yerine geçmez; DNS alias/tünel eşdeğerliğini ispatlamaz.
- Dashboard öğreticisi backend senaryo çalıştırmasından ayrıldı. Son adımda tamamlanınca gizlenir; Guided Run tekrar ilk adımı açar. İsteğe bağlı Gizle düğmesi vardır. Görünürlük/ilerleme kullanıcı ve organizasyon bazında tarayıcı localStorage'ında tutulur, diğer cihazlara senkronize edilmez. Hiçbir tarama/müdahale/rapor üretme isteği göndermez. Gerçek senaryo çalıştırma Scenarios sayfasında kalır.
- Bildirim ve profil menüsü için sağ hizalama, 8 px açıklık ve ekran sınırı koruması kullanılır. Önceden eklenmiş body zoom / Radix portal telafisi korunmuştur. Bildirim listesi kullanılabilir ekran yüksekliğine göre sınırlanır. Dar ekranda header düğmeleri sadeleşir; Guided Run ikonundan erişilebilir.

## Yayından önce gerekli env geçişi

**Yeni sürümü bu ayarlar tamamlanmadan production'a deploy etmeyin.** Uzak DB hedef kontrolü varsayılan olarak bağlantıyı reddeder; bu bilinçli güvenlik kapısıdır.

1. Production hedefini doğru Vercel projesinin `DATABASE_URL` değeriyle güvenli ortamda doğrula. URL'yi loglama, sohbete veya Git'e koyma. `npm run db:target:inspect` yalnızca hedef parmak izlerini gösterir; bağlanmaz ve hedefi onaylamaz.
2. Production için `HCSC_DATABASE_TARGET_FINGERPRINT` ve `HCSC_PRODUCTION_DATABASE_FINGERPRINT` aynı, doğrulanmış production hedefinin SHA-256 çıktısı olmalıdır.
3. Development/Preview için ayrı boş DB/Neon branch ve ayrı DB rolü kullan. `DATABASE_URL` ve varsa `DIRECT_URL` bu hedefe ait olmalıdır. `HCSC_DATABASE_TARGET_FINGERPRINT` bu farklı hedefin, `HCSC_PRODUCTION_DATABASE_FINGERPRINT` ise production'ın parmak izidir. Production fingerprint'ini test hedefiyle değiştirerek korumayı aşmayın.
4. Vercel ortamı `VERCEL_ENV` ile belirlenir. Vercel dışındaki sunucularda `HCSC_DEPLOYMENT_ENV=development|test|preview|production` açıkça ayarlanabilir. Production'a `.env.example` içindeki development değerini körlemesine kopyalamayın.
5. `npm run db:isolation:check` başarılı olmadan seed, test hesabı veya migrasyon çalıştırmayın. Localhost kabulü, o portun production tüneli olmadığı varsayımına dayanır; production tüneli kullanmayın.
6. Production webhook'ları için `HCSC_OUTBOUND_ALLOWED_HOSTS=hooks.example.com,events.example.org` gibi yalnızca yetkili gerçek hostları yazın. `INTEGRATION_ENCRYPTION_KEY` eksikse güvenli secret deposunda oluşturun; mevcut şifreli veriler varsa anahtarı rastgele değiştirmeyin.
7. İzole DB migrasyonu ve gerçek bağlantı testlerinden sonra tüm quality gate'leri, aday deployment health/MFA/e-posta akışını doğrula; sonra kontrollü yayın yap.

- Güncel sonuç: **41 birim + 26 sunucu testi**, lint, TypeScript, Prisma validate ve diff kontrolü başarılı.
- DB URL'leri yalnızca geçici sunucu sürecinde boş bırakılarak `127.0.0.1:3002` üzerinden gerçek Next HTTP testi yapıldı: `/api/health/ready` JSON **503** (`not_ready`, `database.not_configured`), `/api/health/live` **200**. - Sıradaki kapı aynı: doğrulanmış HCSC Neon projesinde üretim satırları kopyalanmadan izole test branch'i; ardından yerel URL değişikliği için açık onay, migrasyon ve gerçek kullanıcı/2FA/e-posta testleri. Bu doğrulamalar olmadan production yayını yapılmadı.

- [IANA IPv4 özel kayıtları](https://www.iana.org/assignments/iana-ipv4-special-registry/), [IANA IPv6 özel kayıtları](https://www.iana.org/assignments/iana-ipv6-special-registry/): muhafazakâr genel ağ adresi politikası. Ağ seviyesinde egress engeli ayrıca gereklidir.
